# Архитектура проекта «Печатает Максим»

## Продуктовые поверхности

### Публичная страница

- Точка входа: `index.html`.
- Стили: `css/style.css`, `css/hero-v03.css`, `css/products-v04.css`.
- Поведение: `js/app.js`.
- Задачи: объяснить продукт, показать материалы, ответить на вопросы и подготовить заявку.

### Studio

- Точка входа: `studio/index.html`.
- Основные стили: `studio/assets/css/app.css` и `mobile-products.css`.
- Production-runtime: `geometry.js` → `layout.js` → `trace-engine.js` →
  `app.js` → `mobile-products.js`.
- Задачи: принять логотип или текст, подготовить макет, настроить продукты и сформировать заявку.

## Модель Studio

`studio/assets/js/app.js` остаётся главным координатором:

- хранит состояние проекта;
- нормализует общий и индивидуальный контент ленты/стикера;
- загружает SVG, PNG, JPEG и первую страницу PDF;
- выполняет crop и готовит одноцветную маску растров;
- передаёт маску в `trace-engine.js`, который строит SVG-контуры через
  `trace-worker.js` и локальную копию ImageTracerJS;
- вызывает геометрию и layout для всех предпросмотров;
- рассчитывает автоматический шаг повтора ленты по ширине композиции и сохраняет ручной шаг для явно изменённых проектов;
- сохраняет восстанавливаемую часть проекта в `localStorage`;
- формирует структурированную заявку и production-SVG для серверного приёмника;
- сохраняет текстовую копию на устройстве как резервный сценарий.

`geometry.js` отвечает за физические печатные границы. `layout.js` рассчитывает единое размещение логотипа и текста. `mobile-products.js` синхронизирует мобильный интерактивный предпросмотр с основным состоянием через DOM-события и визуализирует соседние раппорты ленты.

## Состояние и хранение

- Ключ текущего проекта: `ribbon-studio-v042`.
- Производные `data:`-изображения не сохраняются, если их можно восстановить из SVG-источника.
- Растровый оригинал и параметры crop сохраняются только внутри соответствующего logo-asset.
- Ошибки восстановления не должны мешать чистому запуску Studio.

## Заявки

Studio отправляет заявку в `POST /api/orders/`. PHP-приёмник проверяет входные
данные и SVG, защищает отправку idempotency key, ограничивает частоту и атомарно
сохраняет комплект вне web-root. Номер заявки возвращается только после записи
основного архива.

Telegram, MAX и Google Apps Script подключаются приватной серверной
конфигурацией и не являются источником правды: ошибка уведомления не отменяет
принятую заявку. Google Apps Script дублирует файлы в Drive и строку в Sheets.
Локальный `.txt` остаётся доступным пользователю как резерв при сетевой ошибке.
Подробная настройка описана в
[`ORDER_RECEIVER_RUNBOOK.md`](ORDER_RECEIVER_RUNBOOK.md).

Публичная страница пока продолжает создавать `.txt` локально; её форма не
подменяет реализованный приёмник Studio.

## Публикация

`scripts/build-deploy.mjs` формирует каталог `_site` из публичной страницы,
Studio и их runtime-ресурсов. В artifact не входят документация, тесты,
исторические прототипы и инструменты разработки.

Workflow `Deploy to REG.RU` сохраняет artifact, синхронизирует его с web-root и
проверяет production `version.json`, главную страницу, Studio, robots и sitemap.
`.well-known` исключён из удаления, чтобы deployment не затрагивал служебные
файлы домена. Старые URL `constructor.html` и
`ribbon-studio-design-system-v1.html` получают минимальные страницы-переходы в
актуальную `/studio/`, поэтому сохранённые ссылки не ведут на исторический
runtime.

Проверки разделены на три уровня:

- `check:fast` проверяет изменённые файлы локально;
- `check:pr` является обязательной проверкой Pull Request и включает
  критические Playwright-сценарии;
- `check:full` выполняет полный regression вручную и по расписанию.

Deployment не повторяет quality gate: защищённый `main` уже принимает только
прошедший PR. Workflow собирает artifact, сохраняет его, публикует на REG.RU и
проверяет production. Deployment выполняются последовательно, не отменяют уже
начатую синхронизацию и связаны с GitHub Environment `production`.

## Исторические исходники

Ранние заготовки `studio/components/`, исторический конструктор и визуальный
прототип удалены после проверки runtime и внешних ссылок. Старые публичные URL
`constructor.html` и `ribbon-studio-design-system-v1.html` остаются частью
deployment-контракта и генерируются как переходы на `/studio/`.

## Технические риски

1. `studio/assets/js/app.js` и `app.css` слишком велики для безопасного параллельного развития.
2. SVG очищается частично; нужен отдельный строгий sanitizer и лимиты файлов.
3. Crop и подготовка маски пока выполняются в основном потоке; построение
   SVG-контуров уже вынесено в Web Worker.
4. Для очереди повторных уведомлений нужен отдельный cron и мониторинг
   `notifications.json`.
5. Автоматические проверки ориентированы на Chromium; нужен минимум WebKit для Safari/iPhone.

Порядок устранения рисков зафиксирован в [roadmap](ROADMAP.md).
