# SEO-отчёт интегрированного альтернативного лендинга

**Проверяемая версия:** `prototypes/homepage-alternative/index.html`  
**Статус:** preview, не production  
**Канонический production URL:** `https://печатаетмаксим.рф/`  
**Дата проверки:** 13 августа 2026 года

## Краткий вывод

Интегрированный preview имеет корректную базовую HTML-структуру, русскую локаль, уникальный `<title>`, meta description, один H1, последовательные H2/H3, внутреннюю навигацию по якорям и описательные alt-тексты. UX-связка с Studio также реализована правильно: продуктовые CTA передают только безопасные параметры `product` и `material`.

Однако preview пока **нельзя публиковать как production главную страницу без переноса SEO-обвязки из текущего `index.html`**. В preview отсутствуют `robots`, `canonical`, Open Graph, Twitter Card и JSON-LD Schema.org. Для отдельного неиндексируемого preview это допустимо только при дополнительной защите `noindex`; для публикации на `/` эти поля обязательны.

> Текущая production-главная сохраняет SEO-обвязку. На этапе миграции нужно заменить только контентный слой, а не удалять существующие canonical, JSON-LD, Open Graph, robots и deployment-метаданные.

## 1. Meta-теги и техническая доступность

| Элемент | Текущее состояние preview | Оценка | Действие перед production |
|---|---|---|---|

| `charset` | UTF-8 | Хорошо | Сохранить |
| viewport | Есть | Хорошо | Сохранить |
| `<title>` | `Сделайте упаковку частью бренда — Печатает Максим` | Рабочий, но слишком брендовый | Для production лучше использовать подтверждённый коммерческий title: `Печать лент и наклеек с логотипом — Печатает Максим` |
| `meta description` | `Альтернативная главная страница...` | Непригодно для production | Заменить на фактическое коммерческое описание услуг, без слова «альтернативная» |

| `canonical` | Отсутствует | Критический риск при публикации | Добавить `https://xn--80aaarctnodv3agc9d.xn--p1ai/` |
| Open Graph | Отсутствует | Потеря управляемого social preview | Перенести `og:title`, `og:description`, `og:type`, `og:url`, `og:image`, alt, width и height |

| favicon | Есть SVG | Хорошо | Сохранить абсолютный или корректный root-relative путь |

### Рекомендуемый production head

При переключении на `/` head должен сохранить существующую SEO-модель примерно в таком составе:

```html
<html lang="ru">
<meta name="description" content="Печать сатиновых и силиконовых лент, наклеек и стикеров с логотипом в Нижневартовске и ХМАО. Подготовьте макет онлайн в Studio.">
<meta name="robots" content="index,follow,max-image-preview:large">
<title>Печать лент и наклеек с логотипом — Печатает Максим</title>
<link rel="canonical" href="https://xn--80aaarctnodv3agc9d.xn--p1ai/">
<meta property="og:url" content="https://xn--80aaarctnodv3agc9d.xn--p1ai/">
<meta property="og:type" content="website">
<meta name="twitter:card" content="summary_large_image">
<script type="application/ld+json">...</script>
```

Слово «альтернативная» нужно убрать из production title и description. Оно описывает внутренний статус разработки, а не услугу для пользователя и поисковой системы.

| H2 | `Поможем довести макет до печати` | Доверие и сервис |
| H2 | `Ответы на частые вопросы` | FAQ |

Структура корректна: один H1, затем секционные H2 и предметные H3. Визуальные eyebrow-тексты остаются `<p>`, что правильно: они служат надписями-ориентирами и не создают лишнюю семантическую глубину.

### Рекомендация по H1

Для UX текущий H1 хорошо работает как эмоциональное обещание. Для коммерческого SEO можно оставить его и усилить соседний первый абзац фактическими сущностями: «Печать лент и наклеек с логотипом для упаковки в Нижневартовске и ХМАО». Альтернативный вариант — заменить H1 на `Печать лент и наклеек с логотипом для упаковки`, если приоритетом является более прямое соответствие поисковому намерению.

Не следует добавлять несколько H1 или превращать каждый eyebrow в заголовок: это ухудшит смысловую иерархию без дополнительной пользы.

## 3. Контентные SEO-сигналы

Preview содержит подтверждённые продуктовые сущности: брендированные ленты, стикеры, комплекты, сатин, силикон, логотип, Studio, проверку файла, стоимость, Нижневартовск и доставку по России. Это хорошо согласуется с текущей GEO-стратегией проекта.

Важное ограничение: не добавлять новые товары, регионы, цены, адреса или сроки, если они не подтверждены владельцем. Для генеративного поиска полезнее, чтобы один и тот же набор фактов совпадал на странице, в Studio, JSON-LD, Яндекс Бизнесе, Google Search Console и социальных профилях.

FAQ в preview использует нативный `<details>`, поэтому вопросы доступны пользователю и поисковому роботу без JavaScript. При этом FAQ не нужно автоматически размечать как `FAQPage`, если бизнес не контролирует актуальность ответов и не хочет поддерживать отдельный schema-контракт.

## 5. Внутренние ссылки и параметры Studio

CTA распределены логично:

```text
product=ribbon  → /studio/?product=ribbon
product=sticker → /studio/?product=sticker
product=set     → /studio/?product=set
material=satin  → /studio/?product=ribbon&material=satin
material=silicone → /studio/?product=ribbon&material=silicone
```

Это хороший UX-контракт, но query-URL Studio не должны становиться отдельными индексируемыми страницами. Для `/studio/` нужно сохранить canonical без query. Если production-сервер или поисковый робот видит параметризованный URL, он должен получать тот же canonical на `/studio/`; при необходимости параметризованные варианты можно закрыть `noindex,follow`.

Пути preview вида `/prototypes/homepage-alternative/` нельзя добавлять в sitemap. Перед публикацией на `/` нужно удалить или исключить preview-маршрут из production allowlist либо закрыть его от индексации.

## Итоговая оценка

С точки зрения **структуры контента и UX-связки** preview готов к следующему этапу. С точки зрения **production SEO** он пока готов не полностью: перед публикацией нужно перенести SEO head текущей страницы, настроить canonical/robots для query-вариантов Studio, сохранить JSON-LD и исключить preview-маршрут из индексации.

Это безопасная ситуация: SEO-риски находятся в HTML head и deployment allowlist, а не в дорогой функциональной логике Studio. Их можно исправить отдельным небольшим этапом до замены главной страницы.
