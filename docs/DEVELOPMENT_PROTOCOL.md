## Назначение

Это исполняемый план для владельца проекта, его команды и Codex. Он определяет
порядок изменений среды разработки и одновременно служит журналом фактически
выполненных действий.

GitHub остаётся источником истины для кода. Этот файл отвечает только за текущую
миграцию процесса и после её завершения переносится в историю решений.

## Правила выполнения

1. Выполнять действия строго по порядку внутри текущего этапа.
2. Одновременно держать в статусе `Выполняется` только одно действие.
3. После каждого действия обновлять:
   - статус;
   - фактический результат;
   - доказательство или проверку;
   - следующий идентификатор действия.
4. Не спрашивать владельца о технических деталях, если можно выбрать безопасное
   обратимое решение.
5. Недоступное действие помечать `Блокировано`, записывать точную причину и
   продолжать с независимым действием.
6. Не выполнять commit, push, merge или production deployment без отдельной
   команды владельца.
7. Не совмещать изменение пользовательского UX с изменением инфраструктуры.
8. Рабочий production не отключать до успешной проверки замены.

## Статусы

- `Ожидает` — действие ещё не начато.
- `Выполняется` — текущее действие.
- `Завершено` — результат реализован и проверен.
- `Блокировано` — требуется недоступное разрешение или внешний секрет.
- `Отменено` — действие признано ненужным с зафиксированной причиной.

### P0-A08 — Изолировать production-секреты

- Статус: `Блокировано`.
- Цель: использовать GitHub Environment `production`.
- Выполнено:
  - deployment job связан с environment `production`;
  - задан production URL и минимальное разрешение `deployments: write`;
  - GitHub Environment `production` создан через GitHub CLI;
  - deployment разрешён только из защищённых веток, то есть из `main`;
  - после публикации GitHub будет связывать каждый deploy с отдельной средой.
- Блокировка:
  - GitHub не позволяет прочитать значения существующих repository secrets,
    поэтому их невозможно безопасно скопировать автоматически.
- Осталось после снятия блокировки: вручную повторно добавить `HOST`,
  `USERNAME`, `SSH_PRIVATE_KEY` как environment secrets и затем удалить их
  repository-копии.
- Проверка: GitHub API подтвердил `protected_branches: true`; environment
  secrets пусты, repository secrets содержат три ожидаемых имени.
